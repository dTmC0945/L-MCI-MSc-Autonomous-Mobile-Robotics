9.1 Setting the Environment

ROSRobot Operating System 2Robot Operating System 2 relies on the idea of combining workspaces using the shell environment. [209] In this case, of course, it is our bash shell. The “workspace” is a ROSRobot Operating System 2Robot Operating System 2 term for the location on our system where we’re developing with ROSRobot Operating System 2Robot Operating System 2.

the core ROSRobot Operating System 2Robot Operating System 2 workspace,

Overlay

When developing with ROSRobot Operating System 2Robot Operating System 2, we will typically have several workspaces active concurrently. Combining workspaces makes developing against different versions of ROSRobot Operating System 2Robot Operating System 2, or against different sets of packages, easier. It also allows the installation of several ROSRobot Operating System 2Robot Operating System 2 distributions [210] or “distros”, e.g. Dashing and Eloquent. on the same computer and switching between them. This is accomplished by sourcing setup files every time we open a new shell, or by adding the source command to our shell startup script once.

Warning

Without sourcing the setup files, we won’t have access to ROSRobot Operating System 2Robot Operating System 2 commands, or packages.

In other words, we won’t be able to use ROSRobot Operating System 2Robot Operating System 2. To source the setup, simply type: [211] The exact command depends on where we installed ROSRobot Operating System 2Robot Operating System 2. Of course, if we have installed ROSRobot Operating System 2Robot Operating System 2 using a docker container, this section can be skipped. 

 bash 
 

# Replace ".bash" with your shell if you're not using bash 
# Possible values are: setup.bash, setup.sh, setup.zsh 
source /opt/ros/humble/setup.bash

Sourcing the Script If we don’t want to have to source the setup file every time we open a new shell session, we can add the command to our shell startup script: [212] For our case it is .bashrc 

 bash 
 

# Replace ".bash" with your shell if you're not using bash 
echo "source /opt/ros/humble/setup.bash" » ~/.bashrc

Checking Environment Variables Sourcing ROSRobot Operating System 2Robot Operating System 2 setup files will set several environment variables necessary for operating ROSRobot Operating System 2Robot Operating System 2. If we ever have problems finding or using our ROSRobot Operating System 2Robot Operating System 2 packages, make sure that our environment is properly set up. Here of course to make our lives easy, we use the grep command with -i argument to ignore case as we are searching the output generated by printenv . The ROS Domain ID Variable Once we have determined a unique integer for our group of ROSRobot Operating System 2Robot Operating System 2 nodes, we can set the environment variable with the following: 

 bash 
 

export ROS_DOMAIN_ID=<your_domain_id>

To maintain this setting between shell sessions, add the command to .bashrc :

echo "export ROS_DOMAIN_ID=<your_domain_id>" » ~/.bashrc
¶ Information 9.37: Domain ID v. Namespace

Some clarification is in order here:

  • ROS_DOMAIN_ID is an environment variable used to isolate multiple ROSRobot Operating System 2Robot Operating System 2 systems from each other on the same network. All ROSRobot Operating System 2Robot Operating System 2 nodes use domain ID 0 by default.

  • Namespace in ROSRobot Operating System 2Robot Operating System 2 is a prefix added to node and topic names to logically separate different parts of a single ROSRobot Operating System 2Robot Operating System 2 system.

So ROS_DOMAIN_ID operates at a higher level, they enable differentiation between different systems, whereas namespaces help differentiate within a single system.

Changing the Localhost Variable By default, ROSRobot Operating System 2Robot Operating System 2 communication is NOT limited to localhost. [213] Localhost is a form of hostname, meaning the specific computer the program is running on. It is employed as a method of connecting to services on the network on the physical host machine without the services of an outer network. When using “localhost”, we are connected to our computer or the node addressed by the IP address 127.0.0.1 . The localhost is often used for testing and development, it lets developers run and test Web applications, or any other network service, locally before putting them on a live server. ROS_LOCALHOST_ONLY environment variable allows us to limit ROSRobot Operating System 2Robot Operating System 2 communication to localhost only. This means our ROSRobot Operating System 2Robot Operating System 2 system, and its topics, services, and actions will NOT be visible to other computers on the local network. Using ROS_LOCALHOST_ONLY is helpful in certain settings, such as classrooms, where multiple robots may publish to the same topic causing strange behaviors. We can set the environment variable with the following command: 

 bash 
 

export ROS_LOCALHOST_ONLY=1

Of course, to maintain it across different shell session we can write this command to our .bashrc : 

 bash 
 

echo "export ROS_LOCALHOST_ONLY=1" » ~/.bashrc
